# Google Dialogflow

> Dialogflow is Google Cloud's conversational-agent platform. It ships as two editions on one API
> host: Dialogflow ES (Essentials, API v2) builds intent-and-context agents, and Dialogflow CX —
> now branded Conversational Agents — builds flow-based and generative playbook-based agents on
> API v3. Both are called at https://dialogflow.googleapis.com with a Google OAuth 2.0 bearer
> token. Google publishes no OpenAPI; the first-party machine-readable contract is a Google
> Discovery Document served by the API host itself, plus protobuf IDL in googleapis/googleapis.

## What you need to know before calling it

- Base URL: https://dialogflow.googleapis.com (regional CX agents use https://{region}-dialogflow.googleapis.com)
- Auth: OAuth 2.0 bearer token only. No API key. Two scopes exist and every one of the 437
  operations declares both: https://www.googleapis.com/auth/dialogflow and
  https://www.googleapis.com/auth/cloud-platform
- Errors: google.rpc.Status, not RFC 9457. Branch on error.status (the canonical gRPC name), not on
  error.message.
- Idempotency: none. There is no Idempotency-Key header, no ETag and no If-Match anywhere in the
  contract. A retried create makes a second resource; a retried conversation turn is billed twice.
- Partial update: every PATCH takes an updateMask query parameter. Omitting it REPLACES the whole
  resource.
- Pagination: pageSize + pageToken in, nextPageToken out, on every list operation.
- Long-running work: imports, exports, training, restores and batch operations return a
  google.longrunning.Operation. The response is not the result — poll until done:true.
- Rate limits: published as per-project, per-minute quotas, but NO rate-limit response headers are
  returned. On 429 back off 1 second and double up to 32 seconds (the SLA makes this a customer
  obligation, not advice).
- Billing: every runtime turn is billed, including from the console. Design-time requests are free.

## Events

- Dialogflow calls YOUR endpoint. Webhook fulfillment is a synchronous HTTPS callback on the
  critical path of a billed turn, not a fire-and-forget notification:
  https://cloud.google.com/dialogflow/cx/docs/concept/webhook
- Webhooks are managed API resources in CX (create/list/patch/delete), max 100 per agent.
- Agent Assist conversation events are published to Cloud Pub/Sub.
- No AsyncAPI document is published.

## Agent surfaces

- MCP: Google ships no Model Context Protocol server for Dialogflow. Searched npm and the
  GoogleCloudPlatform and googleapis GitHub orgs on 2026-09-12 — they publish MCP servers for Cloud
  Run, GKE, BigQuery and others, but not for Dialogflow. A candidate tool list derived from real
  operations is in mcp/google-dialogflow-mcp.yml in the repo.
- A2A: no agent card. /.well-known/agent-card.json and /.well-known/agent.json 404 on
  dialogflow.googleapis.com, google.com and developers.google.com; the 200s on cloud.google.com and
  dialogflow.cloud.google.com are HTML shells, not cards.
- Dialogflow CX is a tool CONSUMER: its `tools` resource (max 100 per agent) lets the agent you
  build call external APIs. Nothing lets an external agent client reach in.
